# 建築監造軟體需求清單（草稿）

> 本文件依課程網頁「軟體化切入點」彙整，採四屬性框架描述每個環節：觸發時機、表單欄位、簽核關卡、保存年限。作為事務所監造軟體之需求骨幹。
> >
> >> 來源：https://pp0514-hill.github.io/arch-supervision-course/
> >>
> >> ## 一、系統根節點（L01 法制總覽）
> >>
> >> 案件屬性開關（公共／私人）切換兩套法規與表單模板，是整個系統的根節點。每筆紀錄綁定責任歸屬欄位（監造 vs 專任工程人員）與連帶責任旗標（建築法 §13／§60），作為日後舉證與連帶責任判斷的基礎。

> >> ## 三、四屬性框架
> >>
> >> 每個切入點以四屬性定義：
> >>
> >> **觸發時機**：該環節在工程流程中啟動的時間點或前置條件。
> >>
> >> **表單欄位**：對應的法定表單與必填欄位（如 B14-4、工程會附表五）。
> >>
> >> **簽核關卡**：需經過的審核與簽章節點及順序。
> >>
> >> **保存年限**：紀錄的保存政策（永久或法定年數）。
> >>
> >> ## 四、建議開發優先序
> >>
> >> MVP 應從 L08 的施工日誌與監造報表（B14-4、附表五）開始，因為它是按日填寫、以日期為主鍵的高頻核心。其後依序疊加三個階段：
> >>
> >> **第一階段**：L08 日報表 MVP。
> >>
> >> **第二階段**：L01 案件屬性開關與責任欄位（根節點）、L02 時限引擎與驗收狀態機。
> >>
> >> **第三階段**：L05–L07 查驗留痕、L09–L10 計價與結案、L11 缺失閉環與風險旗標。
